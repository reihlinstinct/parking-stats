# parking-stats

Aggregate-only public statistics from Jerusalem 106 reports (all categories; illegal parking is one of them).

This repository publishes **aggregates only**: counts by month, week,
category, street, neighborhood and hotspot, plus closure-time summaries.
It must never contain raw export data, names, case descriptions or any
per-case detail. The repeat-plates aggregate `data/plates.csv` carries
canonical plates reported three times or more, with report counts only;
license plates are public data (owner decision 2026-11-08). A CI privacy
scan enforces the no-raw-data rule on every push and PR.

Generated by `p106-stats` from
[parking-report-helper](https://github.com/reihlinstinct/parking-report-helper).

## Publishing flow

`p106-stats build` runs **locally** on raw exports (they never leave the
machine and never enter this repo). Its aggregate output directory is then
published with:

```sh
python -m parking_stats.publish OUTPUT_DIR --label "..."
# or, once installed: parking-stats-publish OUTPUT_DIR
```

The publisher re-scans every file, the `--label` text and the rendered
landing page with the privacy rules and refuses to publish on any
finding; only then does it copy `report.html` and `data/` into
`public/`, which GitHub Pages serves. The landing page (stat cards and
inline SVG charts) is built from the same aggregate files; no scripts,
trackers or external resources.

### Heat map

`heatmap.html` is a street-level map: one cell per street with
four reports or more, coordinates rounded to ~111 m, labels carry street
names only (no house numbers). It is inline SVG plus a table with no map
tiles, no third-party scripts and no external requests of any kind, so
viewing it contacts no third party; the only script is the small
first-party zoom/pan helper `data/map.js`, served same-origin under a
strict Content-Security-Policy meta tag (`script-src 'self'`).
Coordinates come from a private street-to-coordinate mapping passed at
publish time (`--geocoding PATH` or `PARKING_STATS_GEOCODING`); like the
filing ledger, that mapping is a local build input and never enters this
repository (`geocoding*.json` is gitignored). Without a mapping the heat
map is skipped and any stale published copy is removed. The heat layer
renders as blurred radial-gradient blobs with a colour ramp by count, a
legend (reading right-to-left for Hebrew: lowest on the right) and
street-name labels with numbered fallbacks for dense clusters. The
initial view is cropped to the dense cluster and centred on the hottest
cells; cells outside it stay in the table with an explicit count note,
and wheel/pinch/drag or the on-map buttons zoom and pan to them (zoom is
capped well above the published ~111 m cell resolution; without
JavaScript the centred static view still renders). A static street-line
basemap (public OpenStreetMap geometry, ODbL, attribution on the page)
is vendored by `scripts/fetch_basemap.py` into
`vendor/basemap-jerusalem.json` - the only networked step, run manually -
and inlined into the map SVG at publish time with a wide margin so
panning still shows streets (`--basemap PATH` or
`PARKING_STATS_BASEMAP`).

### Automatic refresh

The landing page rebuilds itself from the private source every 6 hours, on
every push to main and on demand, then deploys without committing anything.
See [docs/operations/AUTOMATIC-REFRESH.md](docs/operations/AUTOMATIC-REFRESH.md)
for the flow, the private inputs, failure behavior and cost.

### Languages

Every visible word of the generated pages (landing page, heat map, chart
labels, the visit-counter disclosure) comes from one catalog,
`src/parking_stats/catalog.py`. Each language is one block there (code,
its own name, direction, whether it is a machine draft, plural rule), and
the publisher writes one page set per block: the default language keeps
`index.html` and `heatmap.html`, every other language gets
`index.<code>.html` and `heatmap.<code>.html` next to them, so the data
links stay the same. Each page carries a language picker built from the
catalog, showing every language by its own name.

Adding a language is one new block plus one value per key; the tests in
`tests/test_i18n.py` fail until every key has it, and a source scan fails
if a language code appears anywhere else. Non-source languages are machine
drafts until a native speaker reviews them, and their pages say so.

Data is never translated: street, category and neighbourhood names,
plates, the CSV/JSON files and the upstream `report.html` stay as
published.

### What the scanner detects

- Israeli mobile numbers: `05X` / `+972` / `972` / `00972` prefixes, an
  optional `(0)` after an international prefix, and any mix of dashes,
  spaces, dots, slashes or parentheses between the digit groups; the bare
  9-digit prefixless form is caught too.
- Raw municipal export keys (`description`, `caseId`, `case_number`,
  `ClosedDateIncident`), case-insensitive, quoted or not, followed by
  `:` or `=`, and the same names as CSV or TSV header columns.

All matching runs on normalised text: NFKC folding (full-width digits
become ASCII), zero-width characters and BOM removed, no-break spaces
converted to plain spaces.

### Scanner limitations (accepted)

Matching is per line: a phone or key split across a line break is not
detected. License plates are public data (owner decision 2026-11-08) and
no longer scanned.
